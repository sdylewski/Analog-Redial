# VoIP provisioner

A small service that runs next to your Asterisk server and lets each Analog
Redial board claim its own phone number from its web interface: enter the
provisioner's address and an enrollment key once, type a number, press
**Register**. The service creates the SIP account in Asterisk and hands the
credentials back to the board. Nobody edits Asterisk config by hand.

One Python file, standard library only. It needs Python 3.8 or later,
Asterisk with PJSIP, and systemd.

## Install

On the Asterisk host, from a copy of this folder:

```bash
sudo ./install.sh --sip-server pbx.local
```

`--sip-server` is the name or IP address boards should register with. The
installer:

- puts the service in `/opt/redial-provisioner`, its config in
  `/etc/redial-provisioner/config.json` and its records in
  `/var/lib/redial-provisioner`
- writes the generated SIP accounts and dialplan to
  `/etc/asterisk/redial/`, and adds `#include` lines for them to
  `pjsip.conf` and `extensions.conf` (backing both up first)
- adds `include => redial-provisioned` to the `[rotary]` dialplan context,
  where the boards' calls land
- advertises the service on the network (mDNS), so a board's **Find on
  network** button can locate it
- starts the `redial-provisioner` systemd service on port 8077
- prints your first **enrollment key**

Options:

| Option | Default | |
|--------|---------|---|
| `--include-into <context>` | `rotary` | Dialplan context that should be able to call the boards. Repeat it for each context your other phones use, e.g. `--include-into rotary --include-into internal`. The first one is where the boards' own calls land |
| `--permit <cidr>` | anywhere | Only accept SIP registrations from this network, e.g. `--permit 192.168.0.0/24`. Repeatable |
| `--port <n>` | 8077 | Port the service listens on |

Re-running the installer is safe: it keeps your config and keys, and never
adds an include line twice.

If a firewall is running, allow the port from your LAN only:

```bash
sudo ufw allow from 192.168.0.0/24 to any port 8077 proto tcp
```

## On each board

Settings → VOIP → **Automatic setup**:

1. **Find on network**, or type the address, e.g. `http://pbx.local:8077`.
2. Paste the enrollment key and press **Save**.
3. Type the number you'd like, press **Check**, then **Register**. The
   board restarts and connects with the new number.

**Release** gives the number back. Registering a different number on the
same line releases the old one automatically.

## Managing it

Run these on the server. The service picks up changes immediately.

```bash
P="sudo -u asterisk python3 /opt/redial-provisioner/redial_provisioner.py"
C=--config=/etc/redial-provisioner/config.json

$P list $C                       # keys, boards and their numbers
$P release $C 1005               # free a number
$P revoke-board $C a1b2c3d4e5f6  # forget a board and free its numbers
$P regenerate $C                 # rewrite the Asterisk files and reload
sudo python3 /opt/redial-provisioner/redial_provisioner.py add-key $C friends --min 2000 --max 2099
```

**Keys.** Each enrollment key has its own number range and a limit on how
many boards can use it (10 by default). Give each person or household their
own key: you can then delete one key from `config.json` without affecting
anyone else. A board keeps the key it enrolled with and can't be moved to
another key without `revoke-board`.

## How it stays secure

- **Secrets never cross the network.** Every request is signed with
  HMAC-SHA256 over the method, path, a timestamp, a random nonce and the
  body. The service rejects bad signatures, timestamps more than five
  minutes off and reused nonces, so a captured request can't be replayed.
- **Each board gets its own token** on its first registration and uses it
  from then on. The enrollment key is only needed to add a board, so you can
  change or delete it without breaking boards already set up.
- **It can do very little.** Numbers must be digits within the key's range.
  A board can hold at most two (one per line), and only its own. Requests
  are rate-limited, and repeated bad signatures lock that address out for a
  few minutes. The only commands it runs are Asterisk's fixed
  `pjsip show endpoint` and reload commands. It runs as the `asterisk` user
  with a read-only view of the system apart from its own folders.
- **It won't take a number Asterisk already has.** Before creating an
  account it asks Asterisk, so numbers set up by hand or by the older setup
  script show as taken.
- **SIP passwords are random** and generated by the service.

## Running it on the internet

The protocol is designed for this, with three extra steps:

1. **Put it behind HTTPS.** The register response carries a SIP password,
   so over the internet it must be encrypted. Run a reverse proxy such as
   Caddy or nginx with a Let's Encrypt certificate in front of port 8077,
   set `"trust_forwarded_for": true` in `config.json` so rate limits see
   real client addresses, and give boards the `https://` address. Boards
   check the certificate against their built-in root list.
2. **Leave `--permit` off**, since boards will register from anywhere, and
   protect the SIP port with fail2ban or similar.
3. **One key per user**, each with its own number range.

If the Asterisk server also has a trunk to the phone network, read up on
**toll fraud** first: limit outbound dialing to the destinations you mean
to pay for, and set a spending cap with your provider.

## Protocol

All bodies are JSON. Every POST carries
`Authorization: Redial-HMAC id="key:<id>"|"board:<board_id>", ts="<unix>", nonce="<hex>", sig="<hex>"`,
with `sig = HMAC-SHA256(secret, METHOD\nPATH\nts\nnonce\nhex(SHA-256(body)))`.

| Request | Auth | Returns |
|---------|------|---------|
| `GET /api/v1/info` | none | service name, SIP server and port, `server_time` (for boards with no clock) |
| `POST /api/v1/check` `{number}` | key or board | `{available, reason: free / taken / yours}` |
| `POST /api/v1/register` `{board_id, board_name, line, number}` | key or board | SIP `username`, `password`, `sip_server`; plus `board_token` when signed with a key |
| `POST /api/v1/release` `{line}` | board | numbers released |
| `POST /api/v1/status` `{}` | board | this board's numbers |

Errors come back as `{"error": "<code>", "message": "<readable text>"}`.

`redial_provisioner.py client` speaks this protocol for testing:

```bash
./redial_provisioner.py client --url http://pbx.local:8077 --key home.XXXX check 1005
```
