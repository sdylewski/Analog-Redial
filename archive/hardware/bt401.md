# BT401 (DFRobot DFR0781) Bluetooth module: firmware and bring-up

> **Status (2026-10-22): driver written, nothing tested on a real module.**
> No BT401 has been bought or wired yet. Everything here comes from the
> datasheet and DFRobot's Arduino library. When a module is on the bench, work
> through [the bring-up sequence](#bring-up-sequence) and write what happened
> into [the log](#log).

Wiring, pin table and footprint notes: `Bluetooth/DFR0781_BT401/BT401_NOTES.md`.
Sources: `Bluetooth/DFR0781_BT401/` (datasheet, schematic, a copy of
`DFRobot/DFRobot_BT401`, MIT).

## What is in the firmware

| File | What it does |
|--|--|
| `firmware/components/bt_companion/bt401_proto.[ch]` | Pure C: builds `AT+...` lines, splits the reply stream into lines, decodes them, keeps the link/call state. Host-tested. |
| `firmware/components/bt_companion/bt401.[ch]` | The UART and the background task: polls `AT+TS`, folds replies into the state, call control, dialling, bring-up helpers. |
| `bt_companion.c` | Dispatches to `bt401_*` when Settings → Hardware says **BT401 module fitted** (`BOARD_BT_BT401`). |
| `firmware/test/host/test_bt401_proto.c` | Checks the parser and state machine against the datasheet's example lines. Run with `firmware/test/host/run.sh`. |

Console commands (bringup.c): `bt401_probe`, `bt401_at <cmd>`, `bt401_state`,
`bt401_dial <number>`, `bt401_selftest`. `hwcfg bt bt401` and
`first_setup.py --bt-module bt401` choose the module.

The settings value for "BT401" is the same number the removed BK3266 option
used, so a board that had BK3266 saved now reads as BT401.

## Protocol in one screen

Text, 115200 8N1, lines end in CRLF. Host sends `AT+<cmd>[param]`; the module
answers `OK`, `ER+<n>`, or a `<XX>+<value>` line.

| Do | Send | Reply |
|--|--|--|
| status | `AT+TS` | `TS+00` waiting · `01` connected, idle · `02` music · `03` ringing (in or out) · `04` in a call |
| caller / dialled number | `AT+TT` | `TT+<number>` (repeated by the module every 2 s) |
| answer / hang up / reject | `AT+BA04` / `BA03` / `BA02` | `OK` |
| dial | `AT+BT<number>` | `OK`, then `TS+03`, `TS+04` |
| pairing (discoverable) | `AT+BA06` | `OK` |
| drop the phone | `AT+BA01` | `OK` |
| enable calls | `AT+B201` | `OK` (stored by the module) |
| own name / address | `AT+TD` / `AT+TA` | `TD+BT201-AUDIO` / `TA+9EE884AB8BCC` |

The module also volunteers `TS+..` when the state changes, and `QA+30`,
`QM+00` once at power-up. The driver still polls `AT+TS` every 1.5 s to catch a
missed change.

How the driver reads it: `TS+03` is **outgoing** if the driver just sent a dial
command, otherwise **incoming**; `TS+04` is active; `TS+01`/`TS+02`/`TS+00`
end any call. The phone's own name isn't available from the module, so the web
UI shows no paired name.

## Unverified: check these first

1. **Does it answer at all at 115200** (`bt401_probe`: expect `QA+30`/`QM+00`
   within 2 s of power-up, then `TS+..`, `TD+..`, `TA+..`)?
2. **`AT+B201`**: is it needed, is it stored, does it reply `OK`?
3. **`TS+03` for outgoing calls**: does the module report it, or does it jump
   straight to `TS+04`? Does `AT+BT<number>` need the call function enabled
   and a connected phone, as the datasheet says?
4. **Call end**: does hanging up on the phone (or the far end) produce
   `TS+01` promptly, or only on the next poll?
5. **Caller number**: when does `TT+` first appear, and is it empty for a
   withheld number?
6. **`AT+BA06`**: does it make the module discoverable, and for how long?
   Does a phone that was paired before reconnect on its own at power-up?
7. **Audio**: call audio both ways through the J2 mic/speaker path. The mic
   input expects an electret level, the DAC output is headphone level (levels
   in `BT401_NOTES.md`). Set `AT+CA` volume if the earpiece is too quiet.
8. **Music** (`TS+02`): does the handset join it instead of dial tone, as it
   does for the BM64?
9. **Boot order**: the first query goes out 1.5 s after the task starts. Is
   that long enough after power-up?

## Bring-up sequence

1. Wire per `BT401_NOTES.md`, then Settings → Hardware → **BT401 module
   fitted**, reboot (or `hwcfg bt bt401`, then `reboot`).
2. Run `bt_enable 0`, then `bt401_selftest` (no module needed: `PASS`).
3. `bt401_probe`: look for the power-up lines and the three replies. All
   silent means power, crossed TX/RX, or a different baud rate.
4. Pair a phone: `bt401_at BA06`, then find the module on the phone
   ("BT201-AUDIO" by default).
5. `bt_enable 1`, `bt401_state`: connected should read 1.
6. Call the phone's number from another phone; watch the log lines
   `rx: status 3 (ringing)`, `rx: number ...`. Lift the handset: answers.
7. `bt401_dial <number>` and the "dial 1, then the number" route.
8. Record what happened below.
